# kudzuweb/t3code

This is Mauria's fork of `pingdotgg/t3code`. It adds a way to resume Claude Code, Codex and Pi sessions started in a terminal from inside T3, and it keeps the two views of a session in step. Everything else is upstream.

## Known limits

| Limit                                                          | Detail                                                                                                                                                                                                                           |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Codex allows one writer per thread                             | `codex exec resume` is refused with "already has an active writer" while T3's Codex process holds the thread, so a T3 Codex thread can't be continued in a terminal until T3 lets go of it. Claude has no such lock.             |
| Late reply text isn't added                                    | Text a session writes after its turn was already recorded, such as a late Stop-hook continuation, doesn't appear in T3.                                                                                                          |
| Rollback hides later terminal turns                            | Rolling back to an earlier T3 turn also rolls back the terminal turns after it in T3's view. The session file still has them.                                                                                                    |
| A T3 turn sent from an unsynced client can bury terminal turns | If a T3 message is sent from a client that hasn't synced since the terminal turns, those turns are in Claude's context but never shown in T3. Opening the thread, returning to the window and the 10-second poll all sync first. |
| A possible Claude adapter race pauses the sync                 | If an interrupt or shutdown finalizer races a usage update, an ended T3 turn could revert to running and pause the sync until the next T3 turn. This was inferred from the code and never reproduced; it writes nothing wrong.   |
| Codex anchors older than the last 200 messages aren't found    | The sync then writes nothing for that thread until a T3 turn moves the anchor.                                                                                                                                                   |
| Pi is fixture-tested only                                      | `pi` wasn't installed on the machine the sync was built on.                                                                                                                                                                      |

## Syncing with upstream

Run `git fetch upstream`, `git checkout main`, `git merge upstream/main`, then push `main` to `origin`. The fork's `main` is published, so it is merged and never rebased. When a carried upstream fix lands upstream, the merge will usually resolve it, and its row in the table above is then removed.

## Pull requests

Fork PRs are opened with `gh pr create --repo kudzuweb/t3code --base main`, because `gh` run in a fork otherwise targets upstream.
